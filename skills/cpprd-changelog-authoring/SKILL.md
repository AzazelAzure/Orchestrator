# Change Publication and Documentation

Some installations use **CPPRD** for commit, push, pull request, and document.
Treat the acronym as local vocabulary; apply the generic publication procedure.

## Procedure

1. Identify the material change that is actually ready to publish.
2. Select the repository's canonical changelog or publication surface.
3. Write complete content in the same pass; leave no placeholder or empty stub.
4. Match the local format and distinguish verified delivery from planned work.
5. Re-read the pending section and check for related incomplete entries.

## Guardrails

- Do not publish a completion claim before consequential readiness is verified.
- Do not push, open a pull request, or publish externally without authority for that action.
- Keep component and umbrella documentation responsibilities distinct.

## Degraded mode

If publication authority or the canonical documentation surface is unresolved, preserve a local draft and report the missing decision.
