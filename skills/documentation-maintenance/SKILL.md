# Documentation Maintenance

## Procedure

1. Identify docs affected by the change (README, architecture, skills, runtime notes).
2. Update them in the same pass; do not leave empty changelog stubs.
3. Avoid private paths, secrets, and product-adapter branding in tracked docs.
4. State non-claims clearly (no production readiness from candidate alone).
